MineTrigger Bedrock Edition — Switch Pro Controller Input Specification v0.1

## 1. 前提として分かっていること（要点）

- Bedrock Script APIには「攻撃ボタンを押したが何にも当たらなかった（空振り）」を検知する専用イベントが存在しない
  - `entityHitEntity` / `entityHitBlock` は**命中確定時のみ**発火
  - 一方、`itemUse`（何もない方向）/ `itemUseOn`（ブロック方向）/ `playerInteractWithEntity`（エンティティ方向）の3つは、**照準先に関係なくボタンを押した時点で必ずどれか1つが発火する**
  - → 命中判定に頼らず「ボタンが押された」ことだけで確実にトリガーを発動させるには、**ZR（Attack/Mine）ではなく ZL（Use item）系のイベントを起点にする**必要がある
- `InputButton`（`InputInfo.getButtonState` / `PlayerButtonInputAfterEvent`）で生の押下状態を取得できるボタンは **Jump と Sneak の2つだけ**。それ以外のボタン（攻撃・使用・持ち替え等）は個別のボタンコードとして取得できず、必ず「アイテム使用」「ブロック破壊」などの抽象化された行動イベント経由でしか観測できない
- バニラのオフハンドスロットは**盾・トーテム・矢・地図のみ受付**という制限がある。カスタム武器アイテムをそのまま入れられるかは未検証（要プロトタイプ確認）。また「持ち替えて使う」専用ボタンは標準では存在せず、盾は「スニーク（構え）で自動発動」という特殊挙動になっている
- 移動・スロット選択（ホットバー送り）は完全にバニラ動作のまま変更しない

## 4. 未解決の論点（要決定）

### 4-1. オフハンド（二刀流）をどう扱うか

バニラのオフハンドスロットは盾・トーテム・矢・地図しか受け付けない制限があるため、「持ち替えて2本目の武器を使う」という当初案は以下のいずれかに絞る必要がある。

- **案A**：オフハンド運用を諦め、メインハンド1本のみの運用にする（最も確実・実装が単純）
- **案B**：オフハンドスロットには防御系武器（シールド/エスクード）専用と割り切る。これらは元々「盾」の役割に近く、バニラの盾スロット制限と親和性が高い
- **案C**：スクリプトから`container.setItem()`でオフハンドスロットへ直接カスタムアイテムを強制セットできるか検証し、可能なら自由な武器を入れられるようにする（未検証、プロトタイプ要）

### 4-2. オプション武器（Q相当）の扱い

- 独立ボタンが確保できないため、ホットバー内で持ち替えて使う「通常武器の一種」として統合する案が現状の最有力

### 4-3. ZRの扱い

- 何も割り当てず遊ばせておくか、命中前提の補助演出（採掘無効化のみ維持）にするかを決める
